## 1. IDOR (Insecure Direct Object Reference)
**Root cause:** an object id in the request is honored without checking the session *owns* it (broken object-level authorization — API #1 on the OWASP API Top 10).

**Hunting pattern**
- Map every request carrying an identifier: `?id=`, `/users/123`, `uuid`, `order_no`, filenames, `account`, base64/hashed ids, GraphQL `node(id:)`.
- Use **two accounts** (A & B): perform an action as A, then replay with B's id (and vice-versa). Diff the responses.
- Manipulate **location**: body, query, path, headers (`X-User-Id`), cookies, and JSON nesting. Try array/wrapped forms (`id[]=`, `{"id":[self,victim]}`).
- Defeat weak obfuscation: predictable/sequential ids, decodable base64, guessable UUIDv1, incrementing hashes.
- **"Unguessable" ids leaked in-band:** hard-to-guess ProfileId/ImageId/UUIDs are frequently exposed in the victim's own public URLs, page source, or embeds — harvest them there, then replay the id-based (often DELETE) action; unguessability is not authorization (LinkedIn #1608735).
- Test **all verbs** (GET read, but also PUT/PATCH/DELETE for write/destroy) and "minor" actions (logout, expire, share).
- **Zombie / legacy endpoints in mobile apps:** decompile the mobile client to find deprecated but still-live endpoints hardcoded in it — retired routes frequently keep honoring the object id without authorization (Bykea #3085742).
- **Cross-tenant (not just cross-user) authZ:** hold admin on one tenant — repo, org, shop, project — then replay its privileged request with *another* tenant's identifiers. Many checks only prove "is an admin somewhere" instead of "is an admin of this object" (GitHub #3560256).
- **Destructive actions first:** delete/revoke/wipe flows are where a missing ownership check hurts most, and where the subject is most often taken from the request instead of re-derived from the session (Mozilla account deletion via session misbinding #3154983; HackerOne GraphQL `CreateOrUpdateHackerCertification` #2122671). Prioritize mutations/verbs that destroy state.
- **Follow the new features:** freshly shipped areas (ML model registries, beta tabs, internal tools) lag the platform's mature authZ conventions — enumerate their ids first (GitLab ML models #2528293).
- **Third-party / public identifiers as the authorization key:** an app that keys objects on an external platform's id (Steam ID, social handle, phone number) is trusting a value anyone can look up — public discoverability plus a write/delete route is a full IDOR (CS Money #990878). Identity must come from the session, never from a supplied external id.
- **The response is your oracle:** endpoints that echo the affected object back (a deleted comment's body, an updated record) confirm unauthorized access instantly and make id ranges scriptable — sequential ids + destructive verb + echoed object is the classic trifecta (RGhost #861849).
- **Multi-party / marketplace flows:** where two counterparties exchange bids, projects or offers, the check must be 'may this actor see this counterparty's object', not merely 'is this actor authenticated' — leaked bids and project briefs are a business-logic impact, not just disclosure (LinkedIn #2291999).
- **"Can view" is not "can use":** actions that *link* two objects (mark as duplicate, attach, merge, transfer, invite) often authorize only the reader's visibility of the target — e.g. a check of `can?(:view, original_report)` let a report be closed as a duplicate of a report in another program/organization (HackerOne #2516250). Authorize the relationship — same tenant, right role on *both* objects — not merely the ability to see the second one.
- **File-serving / WebDAV layer is an object store too:** authorization enforced in the API is worthless if the raw asset path (DAV, `/remote.php/dav/...`, CDN-style `/files/<id>`) resolves without an ownership check — and "deleted" that only unlinks an object from a listing leaves the direct URL live. Record an asset URL as A, delete it, replay as B; a 200 with the bytes proves it (Nextcloud photos #3518758).
- **Grep the source for the missing check in open-source targets:** absent authorization guards and `TODO`/`FIXME` comments in a controller mark exactly where object access is unverified; pair that with a low-entropy identifier (timestamp-derived token) and the endpoint is reachable unauthenticated (Nextcloud Social #921717). Reading the code beats guessing from the UI.
- **The check lands on the parent, the mutation lands on the child:** hierarchical models (campaign→banner, project→task, album→photo, order→line item) are routinely authorized one level up and never re-checked on the leaf actually being written. Send a request pairing a parent id you legitimately own with another tenant's *child* id — a success proves the guard is on the wrong object (Revive Adserver banner deletion #3401612).
- **Test the *former*-privilege state, not only the never-privileged one:** authorization evaluated at grant time rather than request time leaves revoked admins, removed collaborators and ex-members able to replay privileged mutations against the tenant they used to administer (Stripe Atlas GraphQL co-founder mutation #1066203). Record the mutation while privileged, drop the role, then replay it unchanged.
- **Membership is not a role:** credential-management routes (API keys, tokens, webhooks, integrations) are usually hidden in the UI for low-privilege members but only check org membership server-side — enumerate them from a deliberately basic account, since exposed key material makes it an escalation rather than a permissions nit (DoD #1628012).
- **Deferred / callback actions authorize at schedule time, not run time:** scheduled jobs, webhooks, queued exports and bot callbacks capture a target object id when queued and act on it later — often with a trusted service/bot identity — without re-checking that the requester still has access. Queue the action while a member, then leave the room/org before it fires (Nextcloud Assistant Talk Bot #3799010). Authorize deferred work at execution against the requester's *current* permissions.
- **Object lifecycle state is a separate check on every surface:** deactivated / archived / suspended / soft-deleted objects that the primary route hides are frequently still served by analytics, comparison, export, search-index and recommendation APIs built on a different code path (LinkedIn deactivated company pages via Competitor Analytics API #3604288). Re-request an object in each lifecycle state through every endpoint that touches it.
- **Write-side IDOR = content poisoning:** endpoints that *deposit* into a container named in the request — migration/export archives, backup slots, import staging, batch uploads — are the mirror of read IDOR. Replay with another account's container id; the victim later consumes the artifact as trusted, so an unowned write becomes supply-chain-style injection at restore/import time, not mere disclosure (GitHub Enterprise MigrationFile CVE-2026-1355 #3506183).
- **Historical IDs outlive privacy changes:** harvest old UUIDs/handles from Wayback, cached JS and archived links for resources that were once public and later made private — the server often never re-authorizes them (HackerOne #2483666).
- **Framework blob URLs are bearer tokens:** Rails Active Storage, pre-signed S3 links and similar serve private files to whoever holds the URL. Harvest them from page source/API/embeds and replay in a clean unauthenticated session — the id looks unguessable so nobody added a check (Basecamp fizzy.do #3467641). Route private attachments through an authorizing controller or short-lived session-scoped signed URLs.
- **Legacy file-download handlers are unprotected object stores:** server-rendered handlers inherited from older stacks (`Download.aspx?id=`, `GetFile.ashx`, `download.jsp?docId=`, `/servlet/FileDownload`) are wired straight to a storage table and sit outside the middleware guarding `/api/*` — fingerprint the stack, then grep HTML and JS for those handler paths rather than only the JSON API (DoD attachments, tax forms and contracts #1626508). The mirror case is a paginated *list* endpoint keyed on a container id (`projectId`, `workspaceId`, `orgId`): authorizing the rows is not authorizing the container (SingleStore `GetNotebookScheduledPaginatedJobs` #3219944), and the same holds for analytics/stats query bodies, where the identifier hides in JSON instead of the URL (MoPub `orders/stats/query` #544329).

**Exploit/impact:** read others' data (disclosure IDOR → PII, see [[Exposed APIs & Info Disclosure]]), modify/delete, or escalate (add users — PayPal #415081).

- **Visibility rules enforced only in the UI:** a picker that hides private objects says nothing about the API behind it — replay the action as a raw API call with the id of a private/hidden object (Nextcloud Circles #3511998). Ids exposed in public page source (e.g. LinkedIn `fsd_profile`) make such IDORs free to enumerate (#1734639).

- **Ordering, counting and comparison are read channels:** a sort, search-rank, pagination count or dedupe check that includes objects you cannot read leaks their contents indirectly — insert probe objects with chosen values and binary-search the hidden one from where your probe lands (Trello #0ecb51a3). Pair it with an ID oracle (different responses for existing versus non-existent ids) and amplify with GraphQL aliasing or a `/batch` endpoint, which often accepts far more sub-requests than its docs claim and skips rate limits.

- **Diff the IDOR response against what the UI renders:** a missing ownership check and an over-permissive serializer usually ship together — once cross-user access is confirmed, read the raw JSON for columns the front end never displays (password hashes, reset tokens, `is_admin`, internal hostnames). NASA's `/users/<id>` returned other users' PII *and* the stored `password_` hash (Bugcrowd #fdb0f70d). Rate an IDOR by the fields in the body, not merely by the fact of cross-user access.

- **Protocol siblings of a fixed route:** when a REST endpoint's authorization bug is patched, the same capability's DDP/WebSocket/RPC/GraphQL twin often keeps the old unchecked path. Enumerate every transport that reaches the same server function and replay the call there — Rocket.Chat's `autoTranslate.translateMessage` DDP method never checked `Meteor.userId()` or room membership after the REST route was fixed (HackerOne #3734326).

- **The guard runs on the container, not on each element:** bulk and relationship-forming endpoints authorize the object named in the path once, then loop over attacker-supplied ids in the body without re-checking any of them. Send one id you legitimately own together with one you do not — `TagsController#create_synonyms` checked only the target tag and then merged restricted tags supplied by id (Discourse #3689633).

## 2. Injection — SQLi / XSS / SSTI
**Root cause:** untrusted input crosses into an interpreter without separation/encoding.

**SQL injection**
- Probe: `'`, `"`, `)`, boolean pairs (`' AND 1=1--` vs `' AND 1=2--`), time-based (`SLEEP(5)` / `pg_sleep`), ORDER BY / UNION column counting.
- **Dialect-specific quoting bypasses deny-list regexes:** an identifier filter that misses a DB's raw-string form (PostgreSQL `$tag$...$tag$`, MySQL backticks) lets injection through; user input reaching ORM alias/kwarg names (e.g. `**request.GET` into `annotate`) is unprotected by the ORM (Django #3417967).
- **DB-native Unicode escapes reconstruct filtered characters:** a translation/preprocessor layer (e.g. ADQL→SQL) that forwards a backend's own escape syntax lets `U&'\0027'` (PostgreSQL) become a `'` *after* the quote filter ran — the DB decodes what the filter never saw. Normalize/parametrize before the sink and reject escape syntax the backend will expand (NASA HEASARC TAP #02b11cac).
- Blind → boolean/time oracle; extract via `UNION SELECT` or conditional responses. Automate with **sqlmap** once a param is confirmed.
- Watch non-obvious sinks: search, sort, filters, JSON fields, headers, second-order (stored then used in a query).
- **Injectable path segments:** numeric ids embedded directly in the URL path (`/commenthistory/<id>`) are SQLi sinks just like query params — fuzz the path, not only `?params` (Automattic #1046084).
- **Header-borne SQLi:** values like `User-Agent` / `X-Forwarded-For` logged into a query — fuzz headers with time-based payloads (DoD #2597543).
- **ORM-level / identifier injection:** untrusted input used as a *column name/alias* (not a value) still reaches SQL — e.g. Django `QuerySet.values()/values_list()` built aliases from attacker-controlled JSONField keys (CVE-2024-42005 — IBB #2646493). Keep user input out of identifiers and patch framework CVEs.
- **WAF detection bypass:** a managed ruleset blocking your payload is not a fixed app — mutate the confirmed payload (comments, encodings, whitespace/keyword substitution, moving it between request parts) and re-test; bypasses of even vendor-managed SQLi rulesets are routine (AWS `AWSManagedRulesSQLiRuleSet` — AWS VDP #3591725). Report the app bug, not just the bypass.
- Framework identifier-injection keeps recurring beyond `values()`: Django `FilteredRelation` reached SQL with unsanitized input too (#3292573) — audit every ORM API that takes a *name/alias* rather than a bound value.
- **Type/schema parameters are identifier sinks too:** user-defined *structure* — column type, field type, table/schema names in create-table / add-column / dynamic-report / custom-field features — is concatenated into DDL/DML because placeholders cannot bind types or identifiers (Nextcloud Tables column-type CVE-2026-45545 #3462991). Probe with a valid type plus an appended clause; validate against a fixed allow-list of known-good types.
- **A sanitizer is not a SQL escaper:** the presence of `sanitize_text_field()`, tag-strippers or encoders is a *prompt to check what they defend* — they leave quotes and SQL syntax intact, so interpolating their output into a query is still injectable (WooCommerce `coupon_codes` #3198980). Grep for query construction fed by an XSS-oriented cleaner, and exercise low-privilege reporting roles that assemble ad-hoc aggregate queries.
- **SQLi pivots to OS RCE through the DB's own procedures:** once injection is confirmed on MSSQL/PostgreSQL/etc., check for stored procedures and features that reach the OS (`xp_cmdshell`, `sp_configure` to enable it, `COPY ... PROGRAM`); a blind header SQLi became blind command execution with out-of-band DNS exfiltration (Sony #1339430). Run the DB least-privilege and disable dangerous procedures so injection can't escalate to the host.
- **Secondary subdomains run older code than the flagship app:** documentation, marketing, status, careers and legacy-product hosts inside the same scope are separate stacks, maintained by a different team and frequently outside the main product's review and WAF coverage. Sort enumerated subdomains by how *unlike* the core app they look and test those first — the parameter surface is small but the code can be a decade older (Automattic `docs.atavist.com` #1039315). Attack surface follows the org chart.

- **Sort parameters are a standing sink, and comment asymmetry proves it:** `ORDER BY` cannot take a bind parameter, so sort/order arguments are concatenated by necessity — and front ends that already send raw SQL fragments (`order=publish_date desc,created_at desc`) confirm the value is used as SQL by design. Distinguish "parsed as SQL" from "filtered by a deny-list" without a destructive payload: a *balanced* comment is treated as whitespace (`id/**/desc` and `id/*x*/desc` both yield `id desc`) while an *unbalanced* one errors (`id/*desc`, `id*/desc` → HTTP 403). Only a real parser produces that asymmetry, and the resulting status-code oracle (`200` = valid column, `403` = query failed) is enough to enumerate blind (NASA mars.nasa.gov, Bugcrowd #e1a4a6b9).
- **Non-SQL query languages are the same bug with different syntax:** JQL, LDAP filters, search DSLs and GraphQL filter arguments all concatenate user input into an interpreter. Pair a privileged function with a deliberately failing predicate (`membersOf("jira-administrators")` plus an invalid clause) so the engine resolves the function while composing its *error message* — the error path frequently runs before or outside the permission check (Atlassian JQL #2acd4db2).

**XSS**
- Reflected/Stored/DOM. Inject a context probe (`"><svg onload=alert(1)>`), then tailor to the **output context** (HTML body, attribute, JS string, URL, template).
- Prioritize **stored** XSS rendered to *other/privileged* users (admin panels — Shopify #618031). DOM XSS: trace `source → sink` (`location`→`innerHTML`/`eval`).
- Bypass filters: case, encoding, broken tags, event handlers, `javascript:` URIs, mutation XSS.
- **`javascript:` in a redirect sink via dynamic client registration:** OAuth/OIDC servers (common with MCP) that let clients self-register a `redirect_uri` become second-order XSS if the scheme isn't allow-listed at both registration and redirect (Cloudflare #3316910).
- **SVG upload → stored XSS:** an uploaded SVG served *inline* (not as an attachment) runs embedded `<script>`/event handlers in the site origin — sanitize SVGs or serve user files from a sandbox origin with `Content-Disposition: attachment` (Nextcloud #3357808).
- **Cache poisoning turns reflected into stored:** an input that changes the response but is *not part of the cache key* (odd headers, ignored query params) lets a reflection be cached and then served to every later visitor — reflected XSS on a login page becomes stored XSS for all users (PayPal `/signin` #488147). Always check cache headers and unkeyed inputs before calling a reflection low-impact.
- **Server-side markdown/reference-render flaws → stored XSS:** filters that rewrite reference/link syntax (e.g. GitLab's Banzai `AbstractReferenceFilter`) can be fooled by a partial-match regex into emitting attacker HTML during rendering, giving stored XSS that can bypass CSP — test wiki/issue/comment renderers, validate matches fully, and sanitize after every transform pass (GitLab #2257080).
- **`<base>` tag defeats a nonce CSP:** where HTML injection survives but direct `<script>` is blocked, inject `<base href=//attacker>` — it repoints every *relative* script/resource URL at the attacker origin, and those requests inherit the page's nonce, so a strict nonce-based CSP is satisfied by construction. Enumerate the relative scripts the page loads and host matching paths (GitLab Notes CSP bypass #1481207). Patch the injection point, not the payload.
- **File upload that serves attacker HTML inline is stored XSS:** an upload accepted on an image/extension check but served back inline from a trusted origin with an HTML-ish content-type runs when a victim opens it; on a workspace app that means self-promotion to admin and full takeover (Dust polyglot upload #3115705). Force `Content-Type` and `Content-Disposition: attachment` on downloads, serve user files from a sandbox origin, and never trust the extension.
- **Reflection into a JavaScript response:** input echoed into a `.js` (or JS content-type) response lands directly in code — no HTML tags needed, just breaking the surrounding string/variable context. Test *every* metacharacter, not only quotes: a filter stripping `"` but leaving `>` is still exploitable, and combined with an unkeyed cache it reaches every visitor (Expedia `hav` cookie #1760213).
- **Client-side-only validation:** a field the UI refuses to accept is often unvalidated on the server — replay the request through a proxy with the raw payload before concluding it is filtered, then confirm persistence in the public/share view (Shopify Linkpop #1441988). Payloads that travel through share links have the widest victim set.
- **Chain a reflection with a CSRF-able account-recovery route:** once script runs in the victim's origin, look for a state-changing endpoint whose only protection was the same-origin assumption — the "set a password" route for accounts created through social/third-party login is frequently unprotected, turning reflected XSS into one-click permanent takeover (TikTok #968082). Rate an XSS by what its origin can reach, not by the alert box.
- **The filename is a DOM XSS source, and an injected submit control rides the page's CSRF token:** file pickers / drag-drop zones / "selected file" previews echo `input.files[0].name` (user-controlled before upload) into the DOM — render it with `innerHTML` and it executes. When the sink sits inside an existing authenticated form, inject a `<button formaction=...>` rather than script: the victim's own click submits a state-changing request carrying the legitimate session and anti-CSRF token, bypassing CSRF defences entirely (Basecamp fizzy.do import → 1-click ATO #3608199). Render filenames as text; check what form surrounds any HTML-injection sink.
- **Generated artifacts are their own output context:** HTML/PDF exports, emailed digests, GDPR data downloads, invoices and printable/report views are built by a separate serializer that rarely inherits the live UI's escaping. Plant the payload through the cheapest entry (even an unauthenticated LiveChat visitor), then trigger the export as a privileged user — the file opens from `file://` with no CSP or origin indicator, which is what enables the credential-harvest and exfil variants (Rocket.Chat HTML export #3779690). Escape at every serializer, and rate export-triggered XSS by who opens the file.
- **Every client rendering the stored data is its own output context:** iOS/Android apps, desktop builds and WebView-backed panes re-interpolate values the web front end escapes, so a payload inert in the browser can still fire in the app. Plant out-of-band blind-XSS beacons (not `alert`) in each persisted field — display name, filename, share note, comment, calendar title — then open every surface in each client in turn (Nextcloud iOS #575562). "Not exploitable in the browser" says nothing about the app, and blind payloads are the only practical way to cover sinks you cannot watch.
- **Selector/attribute mismatch in a renderer → stored XSS:** a markup/diagram renderer that *selects* a node with one predicate but *reads its type/attributes* from a different node (parent vs child, first-match vs last, with vs without a fallback) can be fed input that satisfies the safe arm while the payload rides the other — a `pre` block whose `lang` matched one selector arm but was read from the parent injected arbitrary attributes into a generated `img` tag (GitLab Kroki #1731349). Build inputs that split the two passes apart, and treat any attribute flowing into generated HTML as a sink, not only text content.

- **Client-side template injection in framework bindings:** where an Angular-style front end binds stored profile data into the DOM, `{{7*7}}` is as important a probe as a tag — evaluation reaches script through `constructor.constructor(...)()`, and a persisted field turns it into stored XSS for whoever loads the page (WordPress/WooCommerce #250837). Escalate an apparent self-XSS by finding a flow that transfers the poisoned account to a real user (register on an unverified email, victim reclaims it via password reset).

- **Client-side prototype pollution → HTML injection even under CSP:** a query-string parser that maps URL params onto an object without guarding reserved keys (a `backbone.queryparams.js`-style library) lets `__proto__.x=y` write onto `Object.prototype`, which downstream code reads as trusted config. Probe with a harmless canary param and check `Object.prototype` in the console — a quick, site-wide test wherever query strings become objects. A strict CSP that blocks inline script does **not** stop the markup injection that follows: a full-screen injected `iframe` rendering a fake login is a credible phishing primitive on its own (Tesla toolbox, Bugcrowd #57b28008). Rate CSP-limited HTML injection by what the injected markup can do, not by the blocked `alert`.
- **A typed field is not a validated field:** REST/GraphQL schemas that declare `'type' => 'string'` with no `pattern` and no `sanitize_callback` are the write-side tell for stored XSS. Follow the value across three hops — the write (schema/validation), the transform (concatenation into a URL or attribute) and the render (which quoting context it lands in) — because the endpoint that stores it and the one that prints it are usually owned by different code and neither escapes. WordPress stored an attacker's `sub_sizes[].file` verbatim, concatenated it into an image URL and echoed it into a single-quoted `src`, so one `'` broke out (#3931771). Rate the result by the render surface: a list view that draws *every* stored object fires for every admin who opens the screen, with no targeting.
- **MIME deny-lists break on one engine's disagreement:** an upload filter that blocks known-dangerous content types still lets through a type it never considered, and rendering is per-engine — WebKit on iOS treats `video/mp2t` as HTML where desktop Chrome does not. Rewrite only the declared `Content-Type` on an otherwise benign upload, walk the uncommon types, and re-test the served file on mobile engines before calling it inert (Confluence #d5f4aa80).

**SSTI (often → RCE)**
- Probe `{{7*7}}` / `${7*7}` / `#{7*7}` / `{7*7}`; `49` or engine errors confirm.
- Fingerprint the engine (Jinja2, Twig, Freemarker, Smarty, Velocity) then use its object model to reach RCE (e.g. Jinja2 `{{''.__class__.__mro__...}}`, Smarty `{php}` — Unikrn #164224).
- **Stored / second-order SSTI:** the payload sits in a persisted field (e.g. signup First Name) that later feeds a **templated email**; trigger the mail flow and inspect the received message for evaluation (Glovo #1104349).
- **Assume RCE, then prove it:** once evaluation is confirmed and the engine fingerprinted, walk the exposed object graph until an execution primitive (subprocess/shell helper) is reachable — SSTI escalating straight to command injection is the normal outcome, not the exception (curl #3584149).
- **JavaScript template engines count too:** Handlebars, EJS, Pug, lodash templates and friends are SSTI sinks just like Jinja2/Twig — fingerprint the engine first and use *its* object model (compiler internals, prototype access) rather than reusing Python payloads (Shopify Handlebars → RCE #423541).
- **Test harnesses, fixtures and dev servers are in scope:** SSTI sinks hide in code excluded from security review — an echo route in Rails' Action View UJS *test* server rendered request input as an ERB template (Rails #942103). Grep for render/eval calls whose argument is built from `params` rather than a fixed template name, across test and tooling directories too.
- **The sink is often in a dependency:** `_.template`, `Handlebars.compile`, `ejs.render`, `pug.compile` and friends turn a *template string* into code, so audit third-party packages in the same pass as your own render calls. The whole question is whether request-derived data reaches the **template** argument rather than the **data** argument (lodash `_.template` #904672).
- Highest-impact injection — jumps from expression eval to code execution.
- **MongoDB-style query/filter libraries expose a code path:** `sift`, `mingo` and Mongo itself implement `$where`/`$function`/`$expr` by compiling a *string* into a function (`new Function()`). Wherever an API takes a structured filter/query/sort object from the client, try the scripting operator with a benign probe (`6*7`, `typeof process`) before anything else, and read the library version to confirm whether the string path is gated by a flag (Mozilla Taskcluster `filter` → unauth RCE, $12k #3782701). Strip scripting operators from any client-supplied filter.
- **Search / rules / reporting backends inherit their engine's scripting surface:** a parameter forwarded verbatim to Elasticsearch, a rules engine or a report builder can carry engine scripts (Painless, etc.). Prove execution *safely* with an error-code oracle — alternate malformed vs valid scripts and correlate HTTP 500/200 with compile failure/success — then a per-document metadata read (`_seq_no`), all confined to your own documents (HackerOne `sort_query` Painless #3694007). Build queries server-side from an allow-list of fields; never forward client JSON into the engine.

- **Appliance management-console settings are orchestrator template sinks:** free-text config fields (syslog/audit-forward destinations, custom headers, hostnames, certificate fields) are frequently interpolated by the layer that writes the service definition — Nomad and Consul templates, systemd units, log-forwarder configs, cron entries — which runs at root. Probe them with the *orchestrator's* expression syntax, not generic web payloads, and attack the privilege boundary inside the admin UI: a console "editor" who cannot SSH but can write config the root process renders (GitHub Enterprise Server nomad template injection → root SSH #2332623). Fingerprint the orchestration layer first, then test every field that role may edit.

**Insecure deserialization (→ RCE)**
- Spot sinks that deserialize attacker-controlled data (native serializers: Ruby `Marshal`, Java `ObjectInputStream`, Python `pickle`, PHP `unserialize`) — cookies, caches, message queues, upload/import features.
- Escalate via gadget chains in the deserialized object graph to reach code execution (RubyGems #274990). **Patch-gap:** also match exposed enterprise apps/versions to known deserialization CVEs (e.g. Microsoft SharePoint CVE-2019-0604 — DoD #534630), not just custom sinks. Sits in [[RCE]] alongside OS command injection and upload→RCE.
- **Exposed app-server management/messaging endpoints:** JBoss JMX/HTTP invoker & JBossMQ, WebLogic T3, etc. deserialize attacker objects by design — a reachable one is near-guaranteed RCE via gadget chains (Starbucks #221294).
- **Exposed data-platform APIs:** Flink, Spark, Airflow, Jupyter, Hadoop and friends ship unauthenticated management REST APIs whose *intended* features (submit a jar, run a plan, schedule a task) are the execution primitive — fingerprint the interface, read the vendor docs, and use the documented endpoint (Apache Flink `jar/plan` — Aiven #1418891). No memory-safety bug required.
- **Deserialization as an escalation multiplier:** a sink that is unreachable anonymously becomes RCE once you hold *any* write primitive — a SQL injection that seeds a value later deserialized upgraded database access to remote command execution (Liberapay #361341). Trace which stored values are deserialized later and report the chain instead of dismissing either half as "not exploitable alone."
- **A safety flag is only as strong as every deserialization path:** a 'pickling disabled'-style setting can be bypassed by a legacy/fallback loader; shared data buses (queues, caches, Airflow XCom) then bridge a low-privilege writer to a high-privilege reader (Airflow #2334460, CVE-2023-50943).
- **Marketplace / plugin code inherits the platform's trust, not its review:** third-party apps distributed for a self-hosted product run with full server-side privilege — an ownCloud marketplace app's deserialization flaw gave RCE on any instance that installed it (ownCloud #562335). Pull the published plugins and grep their `unserialize`/`pickle`/`readObject` sinks.
- **Custom headers and hidden state fields are deserialization sinks:** attacker-controlled data need not be a body — a `.NET BinaryFormatter` fed from a custom header (`ThumbnailsAccessToken`) gave RCE on Sitecore (CVE-2025-27218 — Mars #3090123), and ASP.NET viewstate-style fields (`__VSTATE`/`__VIEWSTATE`, `LosFormatter`) run gadget chains whenever MAC validation is absent or the key is known (8x8 #1391576). Fingerprint the platform, build the chain for *that* formatter, and confirm with an out-of-band DNS/HTTP callback before anything else.
- **Chain two CVEs inside one component:** where a vendor component offers both an upload primitive and a deserialization sink, the documented path is to place a payload on disk with the first and load it with the second — Telerik UI's weak/known encryption key (CVE-2017-11317) plus its `JavaScriptSerializer` sink (CVE-2019-18935) via `Telerik.Web.UI.WebResource.axd` (DoD #1174185). Fingerprint components from telltale handler paths (`.axd`, `.ashx`, vendor bundles, version strings) and match the version to published CVEs before hunting novel bugs.
- **COTS enterprise suites publish deserializing management servlets:** PeopleSoft, WebLogic, SharePoint, JBoss and Sitecore ship diagnostic, monitoring and integration endpoints that accept serialized objects *by design* and are routinely left reachable when the product is internet-facing. Fingerprint product and version from handler paths, cookies and asset bundles, match that to published CVEs and vendor advisories, then confirm reachability with an out-of-band DNS/HTTP callback before anything else (DoD Oracle PeopleSoft `monitor` service #329376). On these targets patch-gap work outperforms novel bug hunting.

- **Clustering, cache and message-bus ports are a pre-auth deserialization surface:** beyond HTTP management endpoints, the internal ports that products use to form clusters or share caches (Hazelcast `5701`, Java RMI, and similar) often run a custom binary protocol that deserializes attacker input during the join/handshake — *before* any authentication. Bitbucket Data Center's Hazelcast authenticator deserialized handshake data unauthenticated (CVE-2022-26133, Bugcrowd #ce3d9a93). During recon, note every non-HTTP port a clustered product exposes and confirm whether its wire format is a serialized-object protocol; firewall internal cluster/cache ports off untrusted networks and never call a native deserializer on data that arrives before auth.
- **An embedded scripting engine is only as tight as the host objects handed to it:** low-code and automation builders expose a sandbox (Jint, Jurassic, Nashorn, V8) and then pass it host objects for convenience — the escape is the object graph, not an engine bug. Enumerate which host types the script context can reach, look for anything that constructs a serializer, loader, file helper or process wrapper, then abuse the engine's overload-resolution rules to hit a constructor the designers never intended. In .NET, a reachable Newtonsoft `JsonSerializer` with `TypeNameHandling` is an arbitrary-type-instantiation primitive (8x8 Automation Builder, Jint→Newtonsoft coercion, $3,000 #3861550).
- **Server-derived temp paths that only rewrite separators keep the attacker in control:** partial/resumable upload handlers that build a staging file name from the client's path by replacing `/` with `.` leave the final location attacker-chosen, yielding arbitrary read and write; chain the write into an existing deserialization or session-persistence path to reach execution (Tomcat CVE-2025-24813, #3031518). Audit any temp-name derivation for whether it *rejects* or merely *transforms* the supplied path.

**OS command injection**
- Untrusted input reaching a shell (`system`, backticks, `exec`), or **file APIs that overload path vs command** — Ruby `Kernel#open`/`IO.read` execute a name beginning with `|` as a shell command (Ruby rdoc #1161691). Keep untrusted names off `open`; use `File.open`/`File.read`, and never build shell strings from user input.
- **Command-template / token-expansion sinks:** untrusted data substituted into a command *template* (not an obvious `system()` call) still executes — OpenSSH expands a hostname with shell metacharacters via the `%h` token into `ProxyCommand`/`ProxyJump` (CVE-2023-51385 — IBB #2293731). Validate/escape seemingly-benign identifiers (hostnames, filenames) before they reach any command template.
- **Web bugs inside desktop/Electron clients:** the same open redirect, HTML injection or JS injection that rates 'low' in a browser becomes **code execution** when it renders inside a desktop app's trusted origin with access to the privileged bridge — chain redirect → injection → payload (Slack desktop #783877). Always test the desktop build separately from the web app.
- **Build/packaging toolchains are command-injection targets fed by package metadata:** bundlers, CI helpers and IaC synthesizers assemble shell strings (`echo '...'`, `sh -c`, naive single-quote wrapping) from values that include *dependency manifest* fields — version, name, scripts, repo URL — all attacker-controlled the moment one dependency is malicious or typosquatted. A crafted npm version string broke out of `echo '${data}'` and ran commands in CDK's Docker bundling container near AWS creds and source (aws-cdk-lib NodejsFunction #3637898). Single-quote wrapping falls to one `'`; build commands as argument arrays, and treat manifest data as untrusted.
- **Upload → external tool RCE via type disagreement:** when an upload is routed to a media/metadata binary (ExifTool, ImageMagick, ffmpeg, LibreOffice) the *router* usually decides type by extension or declared MIME while the *tool* sniffs the content itself — a file that looks like an image to the gate but is another format to the tool reaches a different, unhardened parser (GitLab Workhorse → ExifTool, CVE-2021-22205 #1154542). Map who decides the type and by what evidence, craft a file that satisfies the two differently (image extension over foreign magic bytes, polyglots), confirm with an OOB callback, sandbox media processing and patch these dependencies promptly.
- **Agent/LLM tool wired to code or shell execution is direct RCE:** a user-facing 'copilot'/agent that exposes a tool like `execute_custom_code`, `run_sql`, or a shell reachable without auth runs attacker input on the backend. Enumerate an agent's tool schema, look for any exec/file/network capability, and prove it non-destructively (nonce digest, hostname echo). Every agent tool must be authenticated, sandboxed and least-privilege (NASA CZDT flood agent #85b61013).
- **Download-then-write with platform-specific separators:** a 'fetch remote file and save locally' feature that sanitizes only `/` is bypassed by Windows `..\` traversal, giving arbitrary file write → RCE (Mozilla VPN #2995025).

- **Serialisation is not shell escaping:** structured data interpolated into a command string (`json.dumps(...)` inside a `shell=True` command template) still breaks out, because JSON encoders escape double quotes but leave single quotes intact — one `'` inside any property closes the argument (NASA Harmony, Bugcrowd #31ad3b26). Probe every JSON/GeoJSON/metadata field that feeds a backend tool with a bare quote before building a payload.

- **Double evaluation is the root of most EL/OGNL/SSTI RCEs:** look for a value rendered by one engine whose *output* a second engine then interprets — a Velocity-rendered Webwork tag whose value contains `$` gets evaluated again as OGNL (CVE-2021-26084). Chase template-in-template rendering rather than a single obvious sink, and expect expression sandboxes (`SafeExpressionUtil` and friends) to fall to unicode-escape encoding of quotes.

- **The clipboard is an untrusted input source:** rich-text and markdown paste handlers that parse `text/html` off a `DataTransfer` object (e.g. a `copy_as_gfm.js`-style converter) are a DOM XSS sink. Host a page that writes crafted markup into the copy buffer, paste into the target's editor, and see whether the handler reconstructs markup instead of escaping it.

- **Batch and multiplex endpoints re-enter routing, so they bypass sanitization:** a nested payload sent to a generic batch route (`/wp-json/batch/v1`, JSON-RPC arrays, GraphQL aliases) can desynchronize dispatch so parameters resolve against a handler that never sanitized them — reaching a raw SQL `NOT IN (...)` clause unauthenticated (Essity #3873072). Fuzz these with nested and repeated sub-requests.

- **A clean scanner result is not evidence of absence:** `sqlmap` and `ghauri` both produced false negatives on a live blind injection; it was confirmed by hand from boolean response differentials and then extracted with a bespoke script (NASA, Bugcrowd #4b4a2cd5). Unlinked pages found via wordlists, sitemaps or archive crawling run the least-maintained query code on a host.

- **Content scanners with a byte budget:** upload validators that inspect only the first N bytes of a file are defeated by padding the payload past the window — phpBB's `check_content()` scanned 256 bytes and also matched a bypassable deny-list, giving stored XSS via SVG (HackerOne #3606773). Pair the padding trick with deny-list-versus-allow-list gaps.

- **Score a DOM XSS by its origin's neighbours, not by the app that contains it:** a low-sensitivity viewer or sandbox sharing an origin with a sensitive authenticated platform upgrades a modest reflection into credentialed exfiltration over same-origin `XHR` (NASA VOTable Viewer pivoting into ARK, Bugcrowd #00cb5011). Inventory everything served from the vulnerable origin before scoring impact.

## 3. Security Misconfigurations
**Root cause:** insecure defaults, permissive policies, exposed surfaces.

**Patterns**
- **Browser-extension `web_accessible_resources` exposed to all origins:** a page an extension declares web-accessible for `all_urls` can be iframed by any site; combined with a persisted permission it triggers a sensitive API silently (Loom `bubble.html` → live webcam #6c751112). Declare the narrowest origins and verify the embedding origin before using camera/mic/capture.
- **CORS:** send `Origin: https://evil.com`; if reflected into `Access-Control-Allow-Origin` **with** `Access-Control-Allow-Credentials: true` → credentialed cross-origin read. Also test `null` origin, sub-domain, suffix/prefix and **substring/`contains`** bypasses (an Origin merely *containing* the allowed host, e.g. `niche.co.evil.net` — X/xAI #426147). Prove with a `fetch(..., {credentials:'include'})` PoC (Zomato #426165, Nord #758785).
- **CORS + default framework endpoint:** loose CORS layered over a framework's default data API (e.g. WordPress `/wp-json/wp/v2/users`) enables unauthenticated cross-origin user enumeration (DoD #1092125).
- **Wildcard-subdomain trust with credentials:** reflecting any `*.target.tld` origin with `Access-Control-Allow-Credentials: true` collapses the origin boundary into the weakest subdomain, and a readable admin response leaks the CSRF nonce that was the last control on state-changing actions (Myndr #3930957). Ask what it takes to obtain *any* subdomain — takeover, user content, staging host — before rating it informational.
- **Default/exposed config:** admin panels with default creds, actuator/debug endpoints (`/actuator`, `/debug`, `phpinfo`), directory listing, `.env`/`.git`/backup files, verbose stack traces.
- **Framework diagnostics as a credential store:** Spring Boot Actuator and friends expose `/actuator/env`, `/heapdump`, `/httptrace` — dump them and mine for session tokens and secrets; this escalates from "info leak" to full account takeover (LY Corporation #862589).
- **Default credentials are recon plus documentation, not brute force:** fingerprint the product behind each exposed console (login page, favicon, title, asset paths), then try only the *vendor-documented* factory pair — this stays in scope and repeatedly lands admin on management UIs (Kinetic Core `admin/admin` #1938693; Spring Boot Admin #954818; DoD admin console #1839012). Rate it by the data the resulting session reaches.
- **Rank exposed hosts by role before triaging:** the same default-credential flaw is far larger on identity infrastructure — SSO servers, IdPs, directory consoles, password vaults — because compromising the authentication provider compromises everything behind it (Remedy SSO #1397786). Map host → role during recon, not after.
- **Unauthenticated infrastructure services:** container registries (`/v2/_catalog`) and orchestration control planes are internet-exposed far more often than expected. A Docker registry leaks proprietary code and secrets baked into layers (Semmle #347296); an exposed Kubernetes API is effectively RCE, because secret reads and pod `exec` live behind the same endpoint (Snapchat #455645). Inventory what actually listens on public addresses.
- **Missing controls:** absent security headers, clickjacking (no `X-Frame-Options`/CSP `frame-ancestors`), open cloud buckets, permissive methods (`TRACE`, `PUT`).
- **`AuthenticatedUsers` ≠ your users:** an S3 ACL granting `AuthenticatedUsers` looks closed to an anonymous probe but is world-readable, since anyone can create an AWS account — always re-test buckets with an arbitrary account's credentials, not only anonymously (GoCD #1654145). Buckets holding internal/admin documents are a perimeter asset and belong in the same audit as an exposed host (DoD #1062803).
- **HTTP method enumeration:** an `OPTIONS` request, or an `Allow` response header advertising enabled verbs, aids recon (OWASP OTG-CONFIG-006) — expose only the methods actually used (Weblate #230648).
- **Subdomain takeover:** dangling CNAME → claim the service (MetaMask #1717626).
- **Decommissioning order is the bug:** the takeover window opens when the *resource* is deleted and the DNS record is left behind (S3 bucket removed, CNAME kept — 8x8 #1089502). Remove DNS first or together with the resource, re-scan after every teardown, and reconcile DNS records against live cloud resources as an inventory task.
- **Per-provider claim flows:** fingerprint the SaaS/PaaS behind each dangling CNAME from its error page (Netlify, Heroku, GitHub Pages, Shopify…) and follow that vendor's documented custom-domain process — takeover is usually just claiming the name in a free account, with no exploit involved (8x8 Netlify #1697402).
- **Acquired / M&A assets:** domains inherited through acquisitions are a rich dangling-CNAME source — inventory acquired domains and clean up unclaimed third-party CNAMEs (Acronis #1256389).
- **Nginx off-by-slash (alias traversal):** an `alias` location missing its trailing slash lets `/<loc>../` climb to the parent dir — request `/<loc>../.git/config` etc. to read source and leaked secrets/tokens (Adobe #1386547).
- **Static / shared mutable state holds per-request security context in mobile clients:** a `static` header map, cookie jar or WebView reused across destinations retains one request's secrets into the next. Decompile and grep for `static` collections in WebView wrappers, then check whether anything clears them between `loadUrl()` calls; pair with weak URL-scheme validation (a `javascript://` payload disguised as an allowed host, `#`-fragment tricks neutralizing appended params) and steer the URL toward a legacy/less-hardened handler to reach the vulnerable path (LinkedIn Android WebViewerFragment cookie theft → ATO #3475626). Per-request context must not live in static fields.
- **Support-system / help-center connectors bridge the external↔internal trust boundary:** ticketing portals, help centers and support integrations accept anonymous input yet are wired into internal wikis, knowledge bases and SSO. Map that plumbing — which internal systems the help center syncs with, whether internal article/attachment ids are addressable from the public portal, whether the integration's service account is over-permissioned — because the bug is usually in the connector, not the wiki (HackerOne internal Confluence access #3113398). Scope support-tool service accounts to exactly the public content.
- **Double clickjacking defeats frame-busting:** opening a new tab while redirecting the *original* tab top-level to the target, then relying on a two-click window-swap, satisfies `X-Frame-Options` and CSP `frame-ancestors` because nothing is ever framed. For any consent/authorize/delete/payment confirmation, don't stop at "framing is blocked" — check whether the confirm button is actionable immediately on load, and require a real same-page user gesture (mouse move / keystroke) before it goes live (WakaTime OAuth #3287060).
- **CDN dangling-CNAME variant — resolves but unclaimed at the provider:** a CNAME that points into a CDN/PaaS (Fastly, Netlify, Heroku…) resolves and the service answers, yet the specific hostname was never registered there — the signature is the provider's unclaimed-host error ("unknown domain") on a host whose DNS looks healthy. Fingerprint the service behind every CNAME and flag those returning the provider's unclaimed response, then claim via the vendor's free custom-domain flow (Mozilla addons-preview-cdn via Fastly #2706358). Reconcile DNS against live CDN/PaaS config as inventory.
- **Add a registrability check to dangling-record triage:** dangling CNAMEs point at ordinary third-party domains as often as at cloud resources, and those can lapse and become purchasable — a `.mil` host resolved to an expired, registrable domain (DoD #2499178). For every CNAME target that fails to resolve, query registrar availability and WHOIS expiry rather than assuming a cloud resource; report from the resolution chain (buying the domain is neither required to prove it nor always permitted).
- **Dependency confusion — public-registry fallback on internal names:** a package manager that falls back to the public registry when an internal name is missing executes whoever registers that name first. Harvest internal package names from JS bundles, source maps, leftover `package.json`, CI logs and Docker layers, check which are unregistered publicly, and claim one with an inert DNS/HTTP beacon (no payload) to prove installation (PayPal npm, $30k #925585). Same shape on PyPI/RubyGems/NuGet/Maven; scope internal names to a private scope/registry and pin resolution.
- **Enumerate a bucket's full verb set, not just read:** `s3 ls`, then `cp` a harmless marker, then remove your own marker. Write access to a bucket the application serves from is content poisoning — stored XSS via uploaded HTML/SVG, a swapped JS bundle, a replaced download — and delete permission is destructive impact on its own, so both rate far above "public bucket" (Zomato `zomato-share` list/upload/delete #229690; Ruby uploads bucket readable *and* writable to any AWS account #209223). Touch only objects you created, and re-test after the fix — partial remediations that close read but leave write are common. Note also that claim paths expire: CloudFront and Azure now require domain-ownership proof, so re-verify an old takeover technique on the current provider before reporting it (GSA CloudFront CNAME #317005).
- **Verification enforced *eventually* is a takeover window:** a PaaS that serves a custom domain before ownership is verified, disabling it only after a grace period, is claimable during that window even though it 'requires verification' — GitLab Pages served unverified custom domains for ~7 days (#2523654). For each provider record three things: does it serve before verification, how long the grace period is, and whether the DNS record must exist at claim time; a grace period survives weekly reconciliation scans.
- **Intranet CORS is reachable through employees' browsers:** permissive `Access-Control-Allow-Origin` on internal-only apps still matters, because any attacker page an employee visits on the corporate network can read those responses (Tesla, Bugcrowd #0e3f3821).

- **Broken link hijacking — dangling *outbound* links, not just DNS:** crawl the target's own pages for links to social handles, app stores, package names, short links and community channels, then check each destination for "not found"/unclaimed status and whether it is still registrable (NASA JPL, Bugcrowd #47e4872e). Hand-typed URLs with typos are a reliable source, and the impersonation inherits the linking page's authority.

- **Default-on diagnostic endpoints are a per-host sweep:** `/server-status`, `/server-info`, `/status`, actuator and similar debug pages ship enabled and unrestricted. The payoff is not the uptime figures but the exact software version and platform fingerprint they hand over for targeting known CVEs.

- **Differential error analysis finds the handler that skipped the middleware:** when one resource on a path correctly denies you, use it as the oracle for its siblings and compare *error shapes* rather than status codes alone — a `403 authorization denied` proves the guard ran, whereas a `400 missing required field` proves the request already reached the handler with no auth boundary in front of it. NASA's LSDA/NLSP ingestion path enforced authorization on some models and never reached it on others, and publicly readable schemas supplied the field names needed to build a valid write (Bugcrowd #2a6e8df3). A validation error is a stronger signal than a success; confirm with clearly marked test records and report them for cleanup.
- **CI runner registration tokens are bearer credentials, not configuration:** GitLab Runner (and equivalent) registration tokens are long-lived and routinely committed to repos, pasted into runbooks or left in `.gitlab-ci.yml` and provisioning scripts. Grep exposed repositories, CI config and docs for registration commands and token prefixes. Registration itself is the proof of impact — a runner that joins the fleet is authorized to receive jobs and the secrets attached to them, and can influence build output — so demonstrate the join and stop, which keeps the supply-chain finding non-destructive (NASA SMCE, Bugcrowd #cc46ad29).
- **The organization's SaaS documents are part of its attack surface:** harvest Google Docs/Sheets, Airtable, Notion and Figma links from public forums, mailing lists, slide decks, PDFs and cached pages in scope, then check each one's permission level while signed out — and check *write* access specifically, because read-only sharing is common and edit access is the finding. Five NASA mission-planning documents were editable by anyone with the link, discovered from a public forum post (Bugcrowd #efe6dc8e). Report integrity and availability, not just disclosure: silent modification of operational data is far harder to detect than a leak.

- **Internal tooling exposed to the internet with self-registration still enabled:** deployments assumed to be gated by corporate SSO frequently leave the application's own signup path on, letting any outside address register and consume internal resources — an internet-facing LibreChat instance granted access to internal foundation models (AWS #3287396). Check registration policy and domain allowlists separately from the login page.
- **Exposed forward proxies turn the `Host` header into an internal name resolver:** an open proxy on a non-standard port forwards by supplied host, giving SSRF-like reach into employee-only services without needing a vulnerable app feature (Reddit #2967634). Mine certificate-transparency data for internal-looking names first, then send them through the proxy.
- **Host-header injection has a third sink beyond cache and reset links — cookie scope:** when the app derives `Set-Cookie` attributes from the request host, a crafted `Host` (or `X-Forwarded-Host`) widens the cookie `Domain` beyond the intended host (NASA, Bugcrowd #fd00af00). Read the response *headers*, not the body, when testing this.

## 4. Broken Authentication & Session Management
**Root cause:** any step in the auth lifecycle trusts attacker-controlled data or uses weak tokens.

**Patterns**
- **Password reset:** token predictability/reuse/no-expiry/not bound to user; **host-header poisoning** of the reset link; token leakage via Referer; account confusion (reset A, token validates for B) — Vimeo #42587.
  - Reset token issued to / valid for **multiple accounts at once**, or a **reusable reset link/cookie** not invalidated on use (UPchieve #1175081, Weblate #1004536).
  - **Reset link delivered to an attacker-supplied address:** if the reset endpoint accepts more than one destination, or takes the address from request input instead of re-deriving it from the stored verified email, submitting victim-account + attacker-email yields a valid token and 0-click takeover (GitLab CVE-2023-7028 — #2293343).
- **OAuth:** missing/observed `state` (CSRF), `redirect_uri` manipulation, code/token leakage, email-binding without verification, implicit-flow token theft.
  - **Pre-account takeover:** register the victim's email before they sign up so a later OAuth login auto-links to the attacker-controlled account; providers that trust the email without reconciling existing accounts merge the identities (Bumble #1074047).
  - **Homograph / normalization bypasses of `redirect_uri`:** probe redirect validation with values a normalizing comparison treats as equivalent — IDN homographs, punycode, added subdomains or paths, trailing characters — rather than an obviously foreign URL; an IDN look-alike passed validation and delivered the access token to the attacker's domain (Semrush #861940). Compare against an exact registered value after normalization, and punycode-decode before display.
- **2FA/OTP:** missing rate-limit (brute OTP), race conditions, response manipulation, backup-code flaws, 2FA not enforced on all flows.
- **A 'lockout' that only changes the response isn't one:** if after N wrong OTPs the server returns a redirect/error but a subsequent correct code still issues a session, the throttle is cosmetic — compare cookie/session issuance, not status codes (SingleStore #3329361).
  - **OTP reuse / non-invalidation:** codes that are not single-use or not rotated when a new one is generated stay replayable within the time step (HackerOne #2529780); also test **mobile / alternate API endpoints** separately — a 2FA gate enforced on the web may be missing or skippable there (Grab #202425).
  - **Empty/blank & non-expiring codes:** an empty OTP can slip past a validator missing a null/empty check (Glassdoor #897385); confirmation/registration tokens that never expire stay replayable to bypass lockout/verification (GSA #264090) — reject empty/malformed input and make codes and tokens single-use and time-bounded.
  - **OTP/secret returned in the response:** the one-time code echoed in the HTTP response body (or a debug field) can be read straight from network traffic, defeating the SMS/email channel entirely (MTN #777957) — deliver verification secrets only out-of-band and never include them in any response.
  - **Enforcement gaps across account state transitions:** map every state an account can hold — active, deactivated, locked, recovering, reactivated — and re-test the second factor from each; enforcement is usually wired to the normal login path only, so deactivate → password reset → login can land an authenticated session with no 2FA challenge (HackerOne #2543342).
  - **Multi-secret forms where only one secret is checked:** when a sensitive action collects two credentials (password *and* backup code), send a deliberately wrong value in each field in turn — disabling 2FA succeeded with an arbitrary password as long as the backup code was valid (HackerOne #587910). A field on the form is not a check on the server.
  - **Guard the capability, not the disable button:** enumerate every *write* on the second factor — enroll, re-enroll, rotate the secret, regenerate backup codes, add a device, change the phone number. Protection is typically wired only to 'disable', so rotating the 2FA secret reaches the same outcome unchallenged; replacing the factor is equivalent to removing it (HackerOne #1139535).
  - **Session minted before the factor is verified:** after valid first-factor credentials but *before* entering any code, inspect the cookie jar and replay an authenticated request straight to a post-login endpoint — if it already carries full privilege, the OTP page is UI, not a state transition (Drugs.com #2315420). A pre-2FA session must be a distinct unprivileged state.
  - **2FA as an access condition for a resource:** where a policy says 'only 2FA-enabled accounts may see X', test X's data endpoint independently of the enrollment flow — check whether the gate is re-evaluated per request and whether a partially completed enrollment already flips the account's `has_2fa` flag (HackerOne private-program invitations #2486086).
  - **Group/role-scoped 2FA policies:** where enforcement is attached to a group, tag or role, attack the membership rather than the policy — check who can create groups and move users between them, and whether enforcement is re-evaluated at login or only when configured (Nextcloud #1050244).
- **Sessions:** predictable/non-rotated session ids, session fixation, cookies without `HttpOnly`/`Secure`/`SameSite`, JWT flaws (`alg:none`, weak secret, no signature check, `kid` injection).
- **Path-normalization differential defeats edge auth:** when a WAF/load-balancer and the backend parse paths differently, prefixing a restricted route with a duplicate or encoded slash (`//-/admin/*`, `/%2f-/admin/*`) slips past the edge rule while the app still normalizes and serves it. Enforce authZ at the application, not only the proxy, and normalize paths identically front-to-back (NASA MODAPS OKAPI #c6b4ca39).
- **JWT verification specifics:** test `alg:none`, algorithm confusion (RS256 verified as HS256 with the public key as the HMAC secret), unvalidated `kid`, and signature stripping — a library that "verifies" using attacker-chosen header parameters verifies nothing (Linktree #1760403). Pin algorithm and key server-side.
- **SSO domain enforcement falls to email input that is not canonicalized:** redirect-to-SSO checks compare the submitted email against protected domains, but a signup that does not strip control characters lets an equivalent-but-different string slip past — appending CRLF (`%0d%0a`) to a protected-domain email bypassed forced SSO and created a local-password account with access to SSO-linked resources (HackerOne/PullRequest #2101076). Reject control/CRLF chars and normalize the email once, before every identity comparison.
- **Enterprise provisioning (SCIM / SAML / JIT) is an auth path:** provisioning usually matches an incoming IdP identity to a local user *by email*. If that match needs no prior verification or domain-ownership proof, an org admin can claim and take over pre-existing accounts (HackerOne #3178999).
- **Stale sessions on credential change:** sessions not invalidated on password change / logout — old sessions in other browsers stay authenticated, so a stolen session survives the victim's remediation; verify server-side revocation across devices (Omise #634488).
- **Step-up re-authentication that isn't checked:** 'confirm your current password' before a password/email change exists precisely to contain a hijacked session — test whether the server validates it at all (drop the parameter, send it empty, or call the underlying update endpoint directly). A bypass turns a temporary session theft into permanent takeover (X/xAI #970157).
- **Verification gates skipped rather than broken:** email/OTP confirmation is often enforced only by the UI's step order — call the post-verification endpoint directly and see whether the account reaches the 'verified' state without the code (UPchieve #1406471). Enforce it server-side as a state transition.
- **Recovery flows that don't check account existence/state:** password-reset/recovery that never verifies the target account still *exists* lets a deleted account be reclaimed by whoever completes the reset (Weblate #230076) — enumerate reset against deleted/removed/suspended accounts, not just active ones.
- **Per-client factor drift:** mobile and alternate API login endpoints frequently require fewer factors than the web (e.g. SMS code accepted with no password at all — Grab #205000). Enumerate factors per client and test each login endpoint independently; the UI collecting a factor does not mean the server requires it.
- **Alternate authentication handlers skip the factor:** enumerate every method the server accepts — local password, LDAP, CAS, SAML, OAuth, token/API login — and drive each directly rather than through the UI's default path. Second-factor enforcement usually lives inside one handler, so any other method that issues the same session is a bypass by construction (Rocket.Chat: adding the CAS option skipped TOTP — #1448268). Enforce the factor where the session is issued, shared by all handlers.
- **Username enumeration + no rate-limit → brute-force auth bypass:** differential login/reset responses leak valid usernames; an unthrottled login endpoint then allows password brute force to bypass auth (Automattic #209008). Return uniform responses and enforce lockout/rate-limit.
- **Backend over-trusts client-submitted login state:** when auth success is decided from fields the client controls (status flags, user ids, "verified" booleans in the login request/response), tampering them bypasses auth for any account — derive auth state only from server-verified credentials (MTN #1709881).
- **0-click ATO (Remitly #2831902):** chain any of the above so no victim interaction is required.
- **Session/response replay:** capture a full successful-login response, log out, then submit *wrong* credentials and swap in the captured response — if access is granted, tokens are neither invalidated at logout nor bound to the authenticating request, and the same swap erases lockout/`429` responses (WakaTime #3120790). Tokens must be short-lived and bound to their issuing context.
- **SAML XML signature wrapping (XSW):** verify that the SP signs and consumes the *same* element — keep the validly signed assertion intact and add a second attacker-authored assertion elsewhere in the document; the verifier checks one node while the app reads the other, forging any identity up to admin (GitHub Enterprise CVE-2024-6800 — #2579939). Pin which assertion is trusted and delegate validation to a hardened library.
- **Whitelisted-subdomain open redirect -> token theft -> 1-click ATO:** an open redirect on a *trusted/whitelisted* subdomain is as dangerous as one on the main domain — it can bounce an auth redirect carrying a token to the attacker (Hostinger #3081691). Validate redirect targets strictly; never route tokens through redirectable URLs.
- **Unverified email-change flow:** a pending, unconfirmed email change that interacts with account recovery can enable takeover — verify the new address, invalidate unconfirmed changes, and don't let pending changes weaken recovery (Mattermost #1114347).
- **Bind a session to the interface that issued it:** where an app has several front doors (web UI, XML-RPC/JSON-RPC API, mobile, GraphQL) sharing one session store, a session minted by the lowest-privilege interface may be honored by a higher-privilege one. Log in through the weakest door and replay that exact session token against the admin-only API — a valid "logged-in user" session read as "authorized API caller" is privilege escalation (Revive Adserver XML-RPC session reuse CVE-2026-34917 #3672641). Re-check privilege per interface; don't let a shared session store imply shared access level.
- **Documented-private endpoints missing their auth middleware:** use the target's own SDK and API docs as the spec for what *should* be authenticated — the official client's `postPrivate()`/`postPublic()` split is a ready-made list — then replay each "private" route with all credentials stripped. The one route where the middleware was never attached falls out immediately, and a wildcard CORS policy turns that gap into silent cross-origin theft (CoinMate `bitcoinWithdrawalFees` #3676308). Enforce auth centrally so a route cannot be exposed by forgetting to annotate it.
- **A biometric / passcode gate is wired to the primary entry only:** enumerate every *other* way into a protected surface — context menus, share sheets, deep links, widgets, Siri shortcuts, "open in", tabs restored after relaunch, notification taps — and exercise each directly. The gate usually lives on the main path and not on the capability itself (Brave iOS "open in private tab" from the playlist bypassed the Face ID gate #3693295). Attach the check to the protected capability so every caller inherits it.
- **Concurrency is an input to every secret-issuing flow:** endpoints that mint, consume or invalidate a secret — password-reset tokens, OTPs, invite codes, one-time links — frequently share state across requests (a token column overwritten per request, a cache key not scoped to the user). HTTP/2's single-packet attack removes network jitter so requests land in the same millisecond, turning theoretical races into reliable ones (Turbo Intruder, Burp "send group in parallel"); a timed forgot-password race yielded another user's reset token and 0-click ATO (Mars #2142109). Test every such endpoint in parallel, not only sequentially.
- **Signature / pre-signed-URL validators that fail open on a precondition:** a validator that returns *success* on an edge branch (expired timestamp, missing/empty field) instead of failing closed skips the crypto check entirely — ownCloud's PreSignedURL returned valid when `OC-Date`/`OC-Expires` were expired (#2337427); test expiry, malformed and empty variants of every signed request.
- **Web cache deception steals the authenticated response:** the mirror of cache poisoning — instead of getting a payload into the cache, get the *victim's* authenticated page into it. Append a path segment or static-looking suffix the app ignores but the cache treats as a cacheable asset, load it authenticated, then request the same URL anonymously and diff; a 200 on a nonsense path is the tell that routing is loose while the cache keys strictly, and it is fatal when session material is reflected into the URL (Expedia/abritel session token in path #1698316). Mark authenticated responses private regardless of path shape.
- **Pre-verification / deterministic session tokens:** split login into 'token minted' and 'token activated' and test them separately — call the session-creation step twice for one identity and compare tokens; identical values mean the token derives from the identity, not the attempt, so it can be fetched before the victim signs up and becomes valid once they verify (Zenly SMS #1245762). Verification must mint a new token, never activate a previously handed-out one.
- **Federated identity keyed on a mutable claim:** where an app federates to an IdP, check which claim it keys the local account on, whether the user can edit that claim through the IdP's own API, and whether `email_verified` is enforced — Flickr keyed on `email` (not the immutable `sub`), ignored `email_verified`, and normalised case only client-side, so calling Cognito `update-user-attributes` to a case-variant of a victim's address gave takeover (#1342088). Drive the IdP API directly (front-end validation lives only in the browser); probe case variants, Unicode look-alikes and plus-addressing for the normalisation gap.

Map the **whole flow**: signup → login → reset → OAuth → email/phone change → 2FA → session lifecycle.

- **Login policies must hold on every auth path:** group/tenant restrictions checked in the browser SSO flow but not in API bearer-token validation (or app passwords, device tokens) are bypassed by the alternate path — enumerate all ways a session can be minted and test each policy on each (Nextcloud `user_oidc` #3572848).

- **Post-login redirect carriers belong to the auth surface:** `RelayState` (SAML), `redirect_uri`, `next`, `returnTo` and friends are open-redirect sinks evaluated *after* the victim has authenticated, which is exactly when they trust the origin and when tokens may ride in the URL or fragment (NASA VDP, Bugcrowd #a1363cea). Test absolute URLs, protocol-relative `//evil.tld` and normalisation tricks against each carrier separately.

- **Front-end/back-end request-boundary disagreement is a session-theft primitive:** where a CDN or proxy fronts an origin, one may honour `Content-Length` while the other honours `Transfer-Encoding`. Send a request carrying both, time the response to confirm the desync, then park a prefix that appends the *next* victim's request — headers, cookies and tokens — into somewhere you can read. Test CDN-fronted hosts specifically.

- **Registration is an authentication boundary — test mass assignment there:** intercept the signup request and add or alter `role`, `group`, `is_admin` and permission fields, including ones the form never sends but the back end may still bind. A role taken from client input grants admin without ever touching a login flow.

- **The redirect allow-list is usually a regex you can read:** parameters named `continue`, `next`, `returnTo` or `redirect_uri` on an apex domain often trigger a *cross-domain auth handshake* rather than a plain redirect — watch for a one-time transfer token appearing in the outbound URL, which is the finding. Then recover the validating pattern from the JS bundle or its source map and read it for the classic flaws: an unescaped `.` matching any character, a missing `^` or `$` anchor. Khan Academy's `KA_DOMAIN_REGEX` had an unescaped dot, so an attacker-registered domain satisfied it, captured the transfer token and replayed it for a full session (#3723458). Validate redirect targets against an exact host allow-list, never a pattern.
- **The ACS endpoint is unauthenticated by definition — `POST` to it directly:** find `/saml/acs`, `/saml/consume`, `/sso/acs` or `/simplesaml/module.php/saml/sp/saml2-acs.php` and submit a self-made `SAMLResponse` rather than driving the IdP login UI. Escalate in order — no signature at all, then a self-signed signature, then signature wrapping — because the no-signature case is the fastest and is exactly what fails most often: an unsigned response with an arbitrary `NameID` produced a full Drupal admin session in one request (Bugcrowd #abfa03c7). Always map which other hostnames share the CMS instance; an ACS flaw on an obscure domain can own the flagship one.
- **Replay the cookie from a "failed" login before believing the failure:** a login endpoint has two outcomes that must not drift apart — the message and the session. Compare the *whole* response for a wrong password against one for a non-existent username, looking for a `Set-Cookie` or token issued alongside an apparent error, or a front end gating on a flag the backend never enforces; then send the issued cookie to a protected route, which is the actual proof (NASA SIPS admin session minted with any password, Bugcrowd #ac8d1f0e).
- **Dynamic issuer discovery makes the signature check the only boundary:** federated identity asks two questions — is the token signed, and is the signer the issuer we trust for this user. ID4me-style flows resolve the IdP from the identifier the *user types*, so the second question is attacker-influenced by design. On open-source targets read the token path for a decode call standing where a verify call belongs (`parse` vs `verify`, `decode(..., verify: false)`, a JWKS fetched but never applied) — Nextcloud User OIDC skipped JWT signature verification on ID4me, letting a malicious authority impersonate any user ($2,500, CVSS 8.1 #3489490). Require signature verification *and* an issuer allow-list.
- **Password reset is a side door to the "verified" state:** reset and email-verification are two paths to the same account flag, and hardening one rarely hardens the other — running the reset flow against a freshly registered, still-pending account activated it outright. Combine that with a CSRF token served from an unauthenticated endpoint and data APIs that authorize on "is logged in" rather than role or SSO provenance, and a self-service registration chain walks straight past an SSO gate (Essity, 2,480 records #3737516). Exercise the reset flow against accounts in every lifecycle state: pending, unverified, disabled, deleted.
- **Request smuggling turns edge-enforced auth into no auth:** when authentication lives in a reverse proxy rather than the application, a CL.TE/TE.CL desync smuggles a second request past the control for *every* route behind it. Confirm the desync by timing first, then prove impact by smuggling a request to a known-protected path and showing the status move from `401` to `200` (Tesla `/metrics` #5e1f7404).

- **Authorization codes must be single-use *and* checked against their own expiry:** a token-exchange handler that neither consumes the code nor compares the code's issue time lets a leaked code mint fresh tokens indefinitely (Mozilla Taskcluster `services/web-server/src/servers/oauth2.js`, #3734676). Redeem the same code twice, then again after its nominal lifetime, and check *which* timestamp field the expiry test reads.
- **Verification that fetches an attacker-influenced URL is an authorization bypass primitive:** `../` in a signature or verify parameter re-points the check at any endpoint, and a verifier that only tests for HTTP `200` is satisfied by any reachable route — the same traversal then re-routed `DELETE` requests to organization-deletion endpoints (Trello, Bugcrowd #4b84e39f). Signatures must be cryptographic and computed over canonicalized input.
- **Auth state machines that conflate "authenticated" with "nothing left to try":** a transition taken on a shared return code for both the success path and an "unable to proceed" path lets a malicious server end negotiation early — `oldap_state_sasl_resp()` advanced to `OLDAP_STOP` when the mechanism list was merely empty (curl/OpenLDAP CVE-2026-13608, #3822248). Negotiation that ends without positive proof must fail closed.
- **Run the full session-lifecycle matrix, and look at what the replayed session returns:** record the session cookie, then log out, change the password and let it idle, replaying the old value after each event — a `JSESSIONID` that stayed valid also handed back an OAuth access token, converting one stolen cookie into durable API access (NASA, Bugcrowd #553cc72a).

## 5. Exposed APIs & Sensitive Information Disclosure
**Root cause:** data/secrets reachable without proper authorization or never meant to be public.

**Patterns**
- **Secret hunting:** JS bundles & source maps, `.git`/`.env`/backups, open buckets (S3/GCS/Azure), CI/CD logs, error pages, mobile app unpacking; grep key formats; validate scope without abuse (Starbucks #716292). Tools: gitleaks/trufflehog, and [[OSINT]] sources.
- **Secrets in URLs & git history:** live keys/tokens surface in legacy/deprecated URLs, query strings, embeds, `Referer`, and browser history (WakaTime #3098717), and in public repos' **full git history**, where deleted secrets persist (Liberapay #837733) — treat anything ever placed in a URL or committed as leaked, and rotate it.
- **Validate key liveness before reporting:** impact hinges on whether a found key is still active — a non-revoked key is exploitable, a rotated one is noise (Stripo #1047125); client-shipped Google keys (`AIza…`) should be API/referrer-restricted, not merely hidden (Clario #1066410).
- **Insecure key issuance:** signup / key-generation endpoints that mint valid keys for **arbitrary emails** without verification (GSA #266449) — abuse-by-design, not just a leaked secret.
- **Over-scoped API responses:** endpoints return more than the caller should see (other users' PII — HackerOne #196655). GraphQL: introspection, nested resolvers, batching, `node(id:)` IDOR.
- **Recursive introspection is a single-request DoS, not just recon:** where GraphQL enforces no depth/complexity limit, one self-referential `__schema.types.fields.type.fields...` query balloons into megabytes and multi-second backend delays with no auth. Disable introspection in prod and cap query depth/cost (Sorare #2048725).
- **AuthZ regressions after a backend migration:** a framework/architecture change (e.g. HackerOne's move to a class-based GraphQL backend) can silently drop object-level permission checks on newly wired resolvers, re-exposing confidential user/program data — re-audit field/object authorization after any backend refactor (HackerOne #489146).
- **Over-scoped UI components:** configurable widgets / report-builders / dashboard add-ons that fetch more than the current user may see, leaking other users' PII (DoD #819591).
- **Hidden/undocumented endpoints:** fuzz paths & API versions (`/v1` vs `/v2`), old mobile endpoints, debug/internal APIs exposed externally.
- **Schema-vs-docs diff (GraphQL):** introspect the live schema and diff it against the published documentation — operations that exist but are undocumented are usually also unreviewed, and missing authorization is common (Shopify `fileCopy` mutation #981472).
- **Authorization in GraphQL is per-resolver:** one unannotated resolver is a hole in an otherwise protected schema, so probe operations unauthenticated rather than assuming a schema-wide gate (Enjin `platform-core` #3452015). Against an open-source target, locate the resolver and name the middleware/directive the authorized operations carry and it does not — citing the code path speeds triage and proves root cause.
- **Introspection is a recon multiplier:** send the standard `__schema` query to every GraphQL endpoint found in JS bundles and mobile traffic; where it answers, the value is the map — enumerate the mutations and fields the UI never calls, as those are the least likely to have been authorization-reviewed (Shopify Storefront endpoint #2886723).
- **REST-vs-GraphQL parity for privacy settings:** a visibility rule ("private profile", secret group) that REST enforces with a 404 may be missing in the GraphQL resolver for the same object. For every privacy toggle, query the object through GraphQL unauthenticated (e.g. `namespace(fullPath:)`) and diff it against the REST response (GitLab #614355).
- **Salesforce Experience/Community sites expose data via Aura endpoints:** community/portal pages backed by Salesforce serve `/aura` (Lightning) endpoints whose `ContentDocument`, record and `getItems` queries enumerate files and objects (Contact/Account) by sequential id when object-/record-level permissions are misset (DoD #2623715, #2294930) — always probe `/aura` on Salesforce-backed portals for file and record enumeration.
- **Export/download endpoints skip UI authz:** `.csv`/`.json`/`.xlsx` export routes are frequently gated only in the UI — request them directly from an unprivileged (or unauthenticated) account to pull cross-tenant PII (HackerOne #2421796).
- **Account-level protections are often session-layer only:** 2FA and IP allowlisting applied to the web session frequently do not follow the object into the API — request the restricted object by global id and through nested resolvers to see whether the restriction belongs to the object or only to one entry point (HackerOne Team object #342978).
- **Strip credentials and replay:** harvest routes from JS bundles, mobile traffic and vendor docs, then re-issue each request with every cookie, token and auth header removed — endpoints that relied on a gateway rather than their own check fall out immediately (Starbucks partner PII #659248).
- **Info leaks that *chain*:** stack traces → internal hosts/paths, user enumeration via differential responses, metadata endpoints (cloud IMDS via SSRF — see [[Cloud Attack Concepts]]).
- **Format-variant over-serialization:** alternate representations (`.json`/`.xml`/API variants) of a page often bypass view-layer field filtering and return far more than the HTML — e.g. `/reports/:id.json` leaking reporter email/OTP/secret token (HackerOne #3000510). Audit serializers per format.
- **Attachment/file ids resolved at render time:** composition features (summaries, previews, exports, embeds) that build content from a supplied file id often re-fetch it without re-authorizing, disclosing other users' attachments (HackerOne #2442008). Authorize the file object itself at render, not only at upload or via its parent record.
- **Feature flags hide UI, not data:** endpoints behind a staged rollout or limited beta are frequently gated only in the front end — enumerate the calls the new UI makes and check their authorization independently (HackerOne `/skills` #188719). New features deserve an early re-audit, not a post-GA one.
- **Side-channel disclosure (timing + no rate-limit):** data the API refuses to return directly can be reconstructed via response-timing differences plus missing rate limits (X/xAI GraphQL private list members #885539) — use constant-time authorization checks and throttling.
- **Filter arguments are a disclosure channel:** any attribute you allow in a query filter is readable a bit at a time through result counts and ordering, even when the field itself is never returned — and boolean operators reopen what the schema closed (a `where` secure-schema bypassed via `or` — HackerOne #645299). Authorize the filter input itself, including everything reachable through `or`/`not`/nested groups.
- **Redaction applied at the view layer only:** masked, truncated or redacted values frequently still travel in the API payload — redacted JIRA references remained retrievable over GraphQL (HackerOne #2357012). Whenever the UI hides something, request the same object through the API and diff; redact where the data is *served*, not where it is displayed.
- **Secrets leaking across a trust boundary on a destination change:** a client re-selects which endpoint to talk to on a redirect, protocol switch (HTTP→HTTPS) or connection reuse, but often keeps the secret scoped to the *old* endpoint — libcurl sent proxy-A credentials to proxy B after a redirect (CVE-2026-6253 — #3669637). Model each secret's scope and look for state that survives a boundary crossing.
- **Links inside public artifacts are attack surface:** URLs published in disclosed reports, screenshots and support threads point at real fulfilment/survey/shipping workflows that hold PII and are rarely in the threat model — a swag link plus one added parameter exposed other researchers' addresses and phones (HackerOne #1256371). Redaction must cover links, and third-party forms need first-party authZ scrutiny.
- **Trusted-source secret + untrusted-source destination = exfiltration:** the dangerous pattern is a credential taken from a trusted origin (env var, CI secret, keychain) that is *not origin-bound*, combined with a destination read from an untrusted source — a redirect, or a config file discovered by walking parent directories. A malicious `.weblate` dropped in a checked-out repo named an attacker URL, and any CLI command with `WLC_KEY` exported sent the token there (Weblate `wlc` #3825141). Bind every credential to the exact origin it was issued for; config discovered from the filesystem is untrusted input.
- **Proxy-capture / HAR / mitmproxy files in public CI artifacts leak everything on the wire:** when tests route traffic through a capturing proxy, the recorded requests carry every header and token that crossed it, including third-party keys the project never meant to publish. Enumerate a project's public CI logs and artifacts (`.har`, `.log`, `.pcap`, screenshots) and grep for `Authorization`/`x-apikey` and key formats — the leaking secret is often a third party's and still a valid disclosure (Microsoft `x-apikey` in Mozilla CI logs #3243860). Scrub headers from anything shipped publicly.
- **User-hosted same-origin assets are a fingerprinting oracle:** assets served from the app's own domain (SVGs, attachments, avatars) turn any link a victim opens into an authenticated same-origin request that can reveal identifying context usable to tailor a phishing page. SVG is the recurring vehicle because it is treated as an image yet can reference external resources (GitHub Enterprise clicked-link metadata leak CVE-2024-9539 #2505761). Serve user-supplied assets from a separate sandbox origin and strip identifying context from asset fetches.
- **Classify a key before reporting it:** Algolia search-only keys, Stripe publishable `pk_`, Firebase web config, Google Maps browser keys and Sentry public DSNs are *designed* to ship in client code. The test is capability, not secrecy — read the vendor's documentation for that key class, establish what the specific key can actually do (a scope/permissions endpoint where one exists, otherwise a single benign read), and report only where permissions exceed the intended scope, e.g. an Algolia admin key where a search key belongs (1Password, closed informative #2923061). Demonstrated capability is the line between a valid report and noise.
- **Configuration search paths that ship empty are injection points:** an agent/daemon that loads config from a directory absent on a default install lets an attacker who can create that directory (world-writable parent) drop a malicious file that is loaded over the built-in defaults — a planted `agent-launcher-logback.xml` turned GoCD's logging into an exfiltration channel (#3509632). Read each product's documented config search order, list which paths exist by default, and check parent-directory permissions; logging frameworks are the top target because their config languages support substitution and remote appenders. Create and lock every path in the search order at install time.
- **Error logs are an uncontrolled copy of the database:** a handler that logs the *failing statement* rather than the failing operation writes bound PII into log files in plaintext — a reachable `ORDER_ERROR_LOG` held full INSERTs with customer data (DoD #3242830). Fuzz for log files by convention (`*_ERROR_LOG`, `debug.log`, `error_log`, dated/archived variants) at the web root and one level up; log an identifier and the operation, never the statement or its values, and keep logs out of the document root.
- **Tokens that *encode* PII, plus public archives, make the leak permanent:** confirmation/reset/invite/unsubscribe tokens sometimes base64/hex/JWT-encode an email or user id in the clear — Omise's confirmation links embedded the address and the Wayback Machine preserved them (#3210022). Query the Wayback CDX API and similar indexes for a target's hosts, filter for those link paths and decode the token; because archives persist, a rotated secret or expired link is still worth decoding for the PII it carries. Tokens must be opaque random ids resolved server-side.
- **Uploads that leak server memory (heartbleed-shaped):** a buffer sized from a declared length but only partially filled writes leftover memory into the stored object — Bykea's upload endpoint embedded server memory chunks into files landing in S3 (#3228011). Upload small files while varying the declared size (`Content-Length` larger than body, truncated multipart, cut-short chunked), download the stored object, compare its byte length to what was sent, and inspect the tail with `xxd` for headers/tokens; a tail that changes between identical uploads distinguishes leaked memory from static padding. Zero or explicitly size upload buffers and verify stored length against received.
- **A public OpenAPI/Swagger spec is a target map:** an unauthenticated `swagger.yaml`/`openapi.json` (or a hosted Swagger-UI) enumerates hidden endpoints, parameters, auth flows (OAuth2 URLs, CSRF-token retrieval) and upload routes — turning blind API testing into a guided one even when calls still need creds (NASA MEDITOR spec exposure). Grep JS/HTML and try `/swagger.json`, `/openapi.json`, `/v2/api-docs`, `/api-docs`; keep specs behind auth and block indexing.
- **MQTT wildcard + public identity pool breaks tenant isolation:** an unauthenticated Cognito/identity pool that hands out temp creds for AWS IoT Core lets an attacker subscribe to a wildcard topic (`board/#`) and passively harvest every tenant's object ids as users act — fatal when that id is the sole access token. Scope IoT policies to exact per-user topics (Opera pinboards #585d9b4e).
- **Crawler-cached URLs bypass directory auth:** a directory that requires login is still leaked if search engines indexed the files earlier — the cached/indexed URLs open the documents (consent forms, CVs, PII) without ever hitting the auth check (globe.gov indexed consent forms). Dork the host (`site:` + filetype) and open indexed hits directly; remediate with `X-Robots-Tag: noindex`/`robots.txt`, cache-removal requests, and per-file (not just per-directory) authorization.
- **Grade a leaked third-party key by its scope:** confirm non-destructively whether a key found in public repos/files is read-only or write-capable against the vendor API (Zotero group library, Bugcrowd #36c73c74) and whether it unlocks licensed data (Scopus, Bugcrowd #9355808f) — scope decides severity.

- **Mutation payloads are a read surface:** GraphQL authorization reviews tend to cover query resolvers, while the object echoed back by a *write* (an invitation, membership, share or upload record) serialises fields the caller was never allowed to read — `addReportParticipant` returned any user's email from a known username (HackerOne #792927). Enumerate mutations, inspect their return types, and look hardest at objects recently migrated from an older API layer.
- **A second credential source bypasses the first one's scope check:** clients that accept credentials from several places (flag, config file such as `.netrc`, environment, keychain) usually implement the "strip on cross-host redirect" guard on one path only, so a wildcard `default` entry re-attaches the token to the redirect target (curl CVE-2026-3783, HackerOne #3583983). Enumerate every credential source and test each against redirects and proxies.

- **Leftover VCS metadata turns a blind directory into an index:** request `.svn/entries`, `.git/config`, `.git/HEAD` and `.DS_Store` on every host; the recovered repository paths, file lists and checksums are then a map for fetching individual files directly. The finding is the unauthenticated reads it enables, not the metadata file itself.

- **A `403` protects a route, not the resource:** before writing off a forbidden path, look for a parallel representation of the same data — a `.zip`/`.tar.gz` sibling, a backup copy, an export, a cached or mirrored version. Access control is usually applied per route, so the archive of a protected directory is frequently world-readable.

- **Read an export's metadata, not only its rows:** point export and bulk-download endpoints at identifiers you do not own and inspect the generated CSV headers, column names and filenames — internal attribute ids leak there even when the body comes back legitimately empty.

- **Auth supplied by an SDK protects one route, not the app:** where authentication arrives with a framework integration — a bot webhook, an OAuth callback, a payment webhook — rather than as middleware across the application, the neighbouring routes frequently have none. Enumerate the whole route table instead of the route the product is documented around: an internal Teams chatbot's entire API surface was seven routes, of which only the Bot Framework webhook `/api/messages` checked anything, leaving `/api/sessions`, `/api/sessions/<session_id>/history`, `/api/chat` and a `DELETE` open to the internet (Essity #4020767). Note also that a WAF rule filtering a JSON key is not authentication, and the sibling development host almost always shares the deployment while rarely getting the fix first.
- **Legacy file handlers are an unauthenticated object store:** server-rendered download endpoints (`GetVectorFile.php`, `download.jsp`, `GetFile.ashx`, `Download.aspx`) are wired straight to the filesystem and sit outside the middleware guarding the modern `/api/*` routes. Find them by grepping HTML and JavaScript for handler paths rather than crawling the JSON API, then test the filename parameter for traversal sequences *and* absolute paths. Prove impact with an application config file — which usually holds credentials — plus one harmless OS file, and stop there (NASA, Bugcrowd #72e039d9).
- **A URL parameter that pre-fills an AI assistant is an injection sink with the victim's privileges:** parameters such as `rovoChatPrompt` cause the assistant to execute attacker text as if typed, and any outbound render — an image, a link preview, a webhook — is the exfiltration channel, with the stolen data carried in the URL path. Guardrails fall to indirection ("help me identify the bird from the image") rather than to a stated goal (Atlassian Rovo #bf1922fb). A model that can both read private data and fetch an arbitrary URL is a complete exfiltration primitive.

- **Helper-daemon diagnostic routes are production surface:** sidecars and companion services (push/notify daemons, metrics exporters, health shims) ship self-test endpoints assumed to be cluster-internal, which answer unauthenticated and echo internal addressing (Nextcloud `notify_push`, #3513471). Map each auxiliary component's routes separately from the main application's.
- **Response differentials in share-password and identity-verification flows are enumeration oracles:** a password-request step that words its reply differently for the share's intended recipient confirms that address to anyone holding the token (Nextcloud #3507273). The differential may be wording, status code, redirect target, response length or timing — diff responses byte-for-byte, headers included.
- **Audit project visibility across self-hosted VCS instances, not just their sign-in page:** GitLab/Gitea/Gerrit on an organization subdomain expose a project-explore listing that enumerates every public or internal repository, plus raw-file, blob and pipeline-artifact routes that survive a UI lockdown (NASA `git.smce.nasa.gov`, Bugcrowd #b080842d). Default-public project settings after a migration are the usual cause.
- **Ingestion configuration is a credential store:** data-portal and ETL platforms keep upstream endpoints and secrets inside the objects describing a harvest or sync job, and those config objects are often served by the same public read API as the datasets — listing harvest sources yielded internal secrets, an infrastructure map and PII (NASA CKAN, Bugcrowd #2309545f). Enumerate job/connector/source objects, not only content ones.

## Cross-cutting methodology
1. **Recon & map** the whole attack surface (endpoints, params, roles, flows) before poking — [[HTTP (80,443)]], [[OSINT]].
2. **Two-account testing** is the universal IDOR/authZ oracle.
3. **Think in chains:** info leak → IDOR → ATO; CORS → data theft; SSTI → RCE.
4. **Prove impact** with a minimal PoC; score with [[CVSS]]; write clearly (see [[PTES]] reporting).
5. Stay **in scope** and follow each program's rules.
